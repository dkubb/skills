# Test this skill in projects

Give each worker this skill, its linked references, and the usual task and repository inputs.
Do not give extra explanations of how to apply the workflow.
The written guidance must be sufficient without the conversations that produced it.

## Follow current guidance during a trial

Read the latest published version of each skill that you use.
For a draft trial, read the current draft at the supplied path.
For workflow advice, disregard earlier messages and earlier skill versions when their advice is absent from the current skill.
Keep the task's intent, constraints, repository rules, and action approvals in force.

If earlier advice conflicts with the current skill, follow the current workflow guidance and report the conflict.
For example:

> The skill says X, but you told me Y. For now, I am doing X. Is that still the intended guidance?

## Resolve feedback in the written guidance

Ask workers to report all problems, from blockers to small frictions.
If a worker needs extra guidance to apply the workflow, treat that need as feedback on the skill.
Correct missing, unclear, or conflicting guidance in this skill or the reference that owns it.
Then send the skill path and ask the worker to refresh the skill and follow it.
Do not explain the change or prescribe workflow behavior in that refresh message.
Do not answer the workflow question separately from the skill update.

## Interpret the results

If a trial receives extra workflow advice, identify that advice in the existing trial notes.
Do not use that trial alone to show that a new worker could follow the skill without extra advice.
Do not assume that a request to disregard earlier advice removes its influence.
A later trial with a fresh context can test whether the revised guidance is sufficient.
